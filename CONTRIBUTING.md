# Как внести правку

Спасибо, что берётесь. Проект нестандартный — весь код и весь контент живут в одном
`index.html` (~2 МБ), поэтому правила простые, но важные.

## С чего начать

1. `git clone` → `cd physics-quest` → `npm run check`. Должно быть `ИТОГ: OK`.
   Это ваш «зелёный» старт: если до правок проверка падает, сначала почините или спросите в issue.
2. Заведите issue (шаблоны в репозитории есть: 🐛 баг, 📐 ошибка в задании, ✨ предложение).
   Для контента — можно без issue, но номер правки в commit'е сильно ускорит ревью.
3. Ветка: `content/task-k47-answer`, `fix/touch-controls-ios`, `docs/deploy`.

## Что можно править не спрашивая

- опечатки и расхождения в условиях/ответах заданий (и **все три языка** сразу);
- переводы в `LOCALES` и подписи уровней;
- документацию (`README*`, `docs/*`), комментарии в коде;
- баланс уровня (`asteroidInterval`, `tasksToWin`) — с коротким обоснованием в PR;
- `scripts/*` — если проверки становятся строже, а не слабее.

## Чего не делать

- **не форматировать `index.html`** (Prettier/Beautifier «Format on save» — выключить):
  внутри три base64-PDF-строки, перенос в них ломает скачивание конспектов;
- **не менять структуру `<script>`-блоков** (их ровно 5) и не переносить данные после движка;
- **не убирать/не переименовывать** `CONSPECT_PDF_BASE64*`, `LEVELS_CONFIG`, `TASKS_DATABASE*`,
  `LOCALES`, `Storage.KEYS` — на них завязаны и игра, и проверки;
- не добавлять npm-зависимости и сборку: офлайн-одиночество файла — это фича;
- не переводить игру на `type="module"`, `import`, `fetch()` локальных файлов — сломается
  запуск по `file://`, а это основной способ раздачи ученикам;
- не выкладывать в `docs/img/` скриншоты с лицами учеников и персональными данными.

## Как добавить задание

Коротко (подробно — [docs/CONTENT.md](docs/CONTENT.md)):

```js
{
 "id": "p23-custom-1", "type": "numeric", "topic": "pressure", "difficulty": 2,
 "question": { "ru": "…", "en": "…", "kk": "…" },
 "formula": "p = F / S", "correctAnswer": 600, "tolerance": 1,
 "hint": { "ru": "…", "en": "…", "kk": "…" },
 "explanation": { "ru": "…", "en": "…", "kk": "…" }
}
```

Вставить в любой из четырёх массивов заданий (`TASKS_DATABASE`, `TASKS_DATABASE_EXT`,
`TASKS_DATABASE_CH`, `TASKS_DATABASE_EXT2`), `topic` взять из существующих 9, `id` сделать
уникальным во всех массивах. Без `en`/`kk` проверка не пропустит коммит в CI — это намеренно.

## Чек-лист PR

```bash
npm run check          # обязателен: 0 ошибок
npm run smoke          # обязателен для правок интерфейса/движка (нужен `npm install` ради jsdom)
npm run stats          # цифры контента; если изменились — обновить таблицу в README
npm run links          # если трогали внешние ссылки
git diff --stat        # диф не должен выглядеть как «переписан весь файл»
```

Логи в конце PR-описания (вывод `npm run check`) достаточно вставить в блок `<details>` —
шаблон PR уже подготовлен.

## Стиль

- комментарии и текст ошибок — по-русски (проект для русско/казахскоязычной школы);
- в коде игры — 4 пробела, как в существующих `scripts/*` (2 пробела) изменения не требуют:
  скрипты репозитория живут в своём стиле, `index.html` — в своём, «унифицировать» их не надо;
- один commit — одна мысль: «исправлен ответ» и «добавлено 5 заданий» — разные коммиты.
