# Как править монолитный `index.html` и не сломать его

Игра намеренно живёт в одном файле: его можно открыть двойным щелчком, положить на флешку,
раздать по ссылке. Плата за это — файл нельзя править «как обычный проект».

## Главные запреты

1. **Никаких автоформаттеров.** Prettier, Beautify, `eslint --fix`, «Format Document» в редакторе —
   всё это разобьёт три base64-PDF-строки (каждая ≈360 000 символов) и сломает кнопку
   «Скачать конспект». В `.editorconfig` это учтено (`max_line_length = off` для `*.html`),
   но редактор всё равно может предложить «форматировать при сохранении» — отключите для этого файла.
2. **Не переносите строки в данных вручную.** Если очень хочется читаемости — отдельным скриптом,
   а потом `npm run check`.
3. **Не «чистите» файл от `//`-комментариев и маркеров `/* ===== … ===== */`.**
   Это единственная карта содержимого.
4. **Не перекодируйте файл.** Только UTF-8 без BOM; в разметке уже есть `<meta charset="UTF-8">`.
   В BOM кириллица в `<title>` может показаться мусором в старых браузерах.

## Рабочий цикл правки

```bash
npm start                 # http://localhost:8080 — правка «вживую», Ctrl+R
# … правила index.html …
npm run check             # 0 ошибок?
npm run smoke             # если трогали движок/интерфейс: игра должна загрузиться и «сыграть»
git diff --stat           # диф не должен показывать «12000 +++ 12000 ---»
```

Если `git diff` показывает переписанным весь файл — вы случайно поменяли переводы строк (CRLF↔LF)
или концовку файла. В этом репозитории `.gitattributes` фиксирует LF; чтобы починить уже сделанное:

```bash
git checkout -- index.html      # откатить и повторить правку аккуратнее
```

Дифф по `index.html` неудобен из-за длинных строк. Полезные приёмы:

```bash
git diff --word-diff=porcelain index.html | head -40     # пословный диф
git diff -U0 index.html | grep '^[-+][^-+]' | head -20   # только изменённые строки
```

## Правка «на коленке», без клона репозитория

Мелкое исправление (опечатка в условии, неверный ответ) реально сделать и через веб:
на GitHub открыть `index.html` → иконка карандаша → правка → commit. Для монолита на 12 000 строк
веб-редактор тормозит, поэтому так — только для точечных замен. Безопасная последовательность:

1. найти текст через `Ctrl+F` по **уникальной подстроке** (кусочек условия задачи, а не слово «найти»);
2. заменить, ничего вокруг не трогая;
3. скачать файл (кнопка Download) и прогнать локально `npm run check`;
4. только потом коммитить.

## Что обязательно должно остаться в файле

| Элемент | Зачем |
|---|---|
| `<!DOCTYPE html>` и `<meta charset="UTF-8">` | иначе режим quirks / битая кириллица |
| `<html lang="ru" data-lang="ru">` | стартовый язык и переключатель |
| 5 блоков `<script>…</script>` | движок и данные; `check.mjs` сверяет баланс тегов |
| 2 блока `<style>` | оформление |
| `const LOCALES = { ru…, en…, kk… }` | по 368 ключей; без одного языка интерфейс «поедет» |
| `CONSPECT_PDF_BASE64`, `…_EN`, `…_KK` | 3 конспекта PDF; проверка смотрит `%PDF-` и `%%EOF` |
| `const isUnlocked = true;` | эта сборка («all unlocked») открывает все 50 уровней. `false` вернёт пошаговую разблокировку |

## Точки, где чаще всего ломают

- **забытая/лишняя запятая** в массивах заданий → `Unexpected token ']'`;
- **неэкранированная кавычка** внутри `"question": { "ru": "…"тело…" " }`;
- **`</script>`** внутри текста задания — инлайновый скрипт закрывается раньше времени,
  дальше идёт HTML-мусор. Пишите `<\/script>` или `</scr` + `ipt>`;
- **`\n` в строке** — перенос должен быть escape-последовательностью, а не реальным переводом;
- **несогласованные `id`**: `Teacher.getAllTasks()` склеивает 4 массива, дубль id не роняет игру,
  но задание перестаёт корректно отмечаться как решённое (это предупреждение в `check`);
- **новый `topic` без уровня**: задание просто никогда не выпадет;
- **`tasksToWin` больше, чем заданий по теме**: уровень непроходим.

## Перед публикацией репозитория

Публичный репо увидят ученики, коллеги и поисковики. Прогоните глазами:

```bash
grep -o 'https\?://[^"'"'"' )]*' index.html | sort -u | head -80   # все внешние ссылки
grep -nE 'mailto:|@gmail|@mail\.|tel:\+|\+7[ ]?\(?[0-9]{3}' index.html | head
grep -n 'gemini.google.com/share' index.html | wc -l
grep -n 'vimeo.com/reviews' index.html | wc -l
```

Что обычно не хотят публиковать (в этом `index.html` это есть — решение за вами):

- **`gemini.google.com/share/…` (11 ссылок)** в блоках экспериментов — это публичные шаринги
  диалогов: там может быть ваше имя, запросы, куски учебных материалов. Если репозиторий публичный,
  замените на нейтральные ссылки (PhET, видеоуроки) или уберите.
- **`vimeo.com/reviews/…`** — приватная страница ревью видео; у ученика будет «нет доступа».
  Замените на обычную публичную ссылку Vimeo/Rutube/YouTube.
- **Скриншоты и картинки с учениками, ФИО, названия школы** — если добавляете в `docs/`,
  убедитесь, что на них нет персональных данных (в текущем наборе их нет).
- **`assets/pdf/*.pdf`** — конспекты, сгенерированные по материалам учебника. Перед тем как
  публиковать репозиторий открыто, решите, оставляем ли их: 69 страниц × 3 языка, и это самый
  «учебникозависимый» актив. Можно убрать из публичной части, оставив только встроенные в `index.html`.

После любой такой чистки:

```bash
npm run check && npm run links && npm run pdfs
```

Ссылки сами по себе ничего не ломают: без интернета игра работает, просто часть ссылок ведёт
на приватные или личные страницы. Поэтому решение «оставить как есть» вполне рабочее —
но пусть оно будет осознанным, а не обнаруженным после публикации.

## Если нужно «разобрать монолит»

Иногда хочется нормальный проект с `src/js/*.js` и сборкой. Путь:

1. разрезать `index.html` по маркерам `/* ===== … ===== */` (см. карту в [CONTENT.md](CONTENT.md));
2. `build.mjs`: собрать обратно склейкой `<script>`-блоков в исходном порядке (важно! `levels-textbook.js`
   должен идти раньше `js/tasks.js`, потому что `CONSPECT`/`LEVELS_CONFIG` используются позже);
3. сравнить `md5sum` собранного и исходного `index.html` — если совпало, рефакторинг безопасен;
4. не забыть, что игра должна продолжать запускаться по `file://` (никаких `type="module"`,
   `import`, `fetch()` локальных файлов — в Chrome это ломается).
