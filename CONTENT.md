# Как устроен контент игры и как его править

`index.html` — не «минифицированный бинарь», а последовательно склеенные блоки, каждый помечен
комментарием `/* ===== имя ===== */`. Правки обычно сводятся к «найти маркер → поправить массив».
Ниже — карта файла, актуальная для версии 1.0.0 (номера строк смещаются при правках; ориентируйтесь
на маркеры, а не на номера).

## Карта `index.html`

```
строки 1 … 1602      <style>   — всё оформление: 19 секций с комментариями (меню, HUD, модалки…)
строки 1606 … 1636   <style>   — второй, маленький блок (адаптивность/мелочи)
строки 1640 … 2094   HTML      — 8 экранов (.screen) и 6 модалок (.modal)
строки 2095 … 3093   <script>  /* ===== tasks-extended.js ===== */  TASKS_DATABASE_EXT  (50 заданий)
строки 3095 … 4415   <script>  /* ===== tasks-chapters.js ===== */  TASKS_DATABASE_CH   (76: ТБ + лабы)
строки 4417 … 6479   <script>  /* ===== tasks-extra.js ===== */      TASKS_DATABASE_EXT2 (93 задания)
строки 6481 … 7160   <script>  /* ===== levels-textbook.js ===== */  LEVELS_CONFIG, CONSPECT,
                                 LEVEL_THEORY, LAB_WORKS, три PDF в base64 (строки 7041–7043)
строки 7161 … 12379  <script>  — ОДИН большой блок, внутри него маркированные секции:
                                 /* ===== js/tasks.js =====   (7163) */  TASKS_DATABASE (30 заданий)
                                 /* ===== js/levels.js =====  (7755) */  getLevelConfig()
                                 /* ===== js/locales.js ===== (7787) */  LOCALES: ru / en / kk
                                 /* ===== js/storage.js ===== (8972) */  Storage: 6 ключей localStorage
                                 /* ===== js/teacher.js ===== (9167) */  Teacher: задания, уроки, статистика
                                 /* ===== js/game.js =====    (9840) */  движок: canvas, астероиды, РПГ
                                 /* ===== js/i18n.js =====   (11616) */  I18n: язык, t(), переключение
                                 /* ===== js/main.js =====   (11692) */  инициализация и обработчики
строки 12380 … 12381  </body></html>
```

Пять `<script>`-блоков — не «модули»: у них нет изоляции области видимости, это просто склейка.
Порядок важен: данные (`TASKS_DATABASE_EXT*`, `LEVELS_CONFIG`) объявлены раньше движка, а движок
разворачивает интерфейс в конце. Поэтому «вырезать кусок кода вместе с `<script>`» — типичная
причина внезапной смерти игры; `npm run check` ловит это по несбалансированным тегам
и по невыполнимым скриптам.



Экраны (div.screen, активный помечается классом `active`): `loading-screen`, `menu-screen`,
`level-screen`, `profile-screen`, `game-screen`, `teacher-screen`, `gameover-screen`, `victory-screen`.
Модалки: `task-modal`, `theory-modal`, `records-modal`, `howto-modal`, `about-modal`, `conspekt-modal`.

## Данные заданий

Четыре массива сливаются в один рантайм-список (`Teacher.getAllTasks()`), поэтому id должны быть
уникальны **между всеми четырьмя**:

| массив | где | размер | тема в основном |
|---|---|---:|---|
| `TASKS_DATABASE` | js/tasks.js | 30 | базовый набор по всем 9 темам |
| `TASKS_DATABASE_EXT` | tasks-extended.js | 50 | кинематика/динамика/энергия |
| `TASKS_DATABASE_CH` | tasks-chapters.js | 76 | техника безопасности + 10 лабораторных |
| `TASKS_DATABASE_EXT2` | tasks-extra.js | 93 | §1–2 (общее) + §37–39 (космос) |

Итого **249 заданий**. Точную разбивку в текущий момент даёт `npm run stats`,
схему полей по типам — `npm run schema`.

Общая форма объекта задания:

```js
{
 "id": "k47",                     // уникальной строкой; префикс темы удобен: k-, d-, p-, e-, sf-, lab…
 "type": "numeric",               // numeric | multiple-choice | short-answer | fill-blank |
                                  // multi-select | true-false | matching
 "topic": "kinematics",           // одна из: general, kinematics, density, dynamics,
                                  // pressure, energy, mechanical, solar, safety
 "difficulty": 2,                 // 1 | 2 | 3
 "question": { "ru": "…", "en": "…", "kk": "…" },   // обязательны все три языка
 "options": { "ru": [ … ], "en": [ … ], "kk": [ … ] },   // для choice/multi-select
 "correctAnswer": 18,             // число / индекс / текст / true-false / массив — см. тип
 "tolerance": 0.5,                // только numeric: допуск в % или абс. единицах
 "alternatives": [ "18 км/ч" ],   // short-answer/fill-blank: принятые варианты записи
 "formula": "v = S / t",          // подсказка-формула (numeric удобно)
 "hint":        { "ru": "…", "en": "…", "kk": "…" },
 "explanation": { "ru": "…", "en": "…", "kk": "…" }     // показывается после проверки
}
```

Правила, нарушение которых ломает игру (их ловит `npm run check`):

- нет одного из трёх языков в `question` → `check.mjs` валит сборку;
- дубль `id` → предупреждение: задание выпадает из «нерешённых» и уровни зацикливаются;
- `type` не из списка → модалка задания отрисуется пустой;
- `multiple-choice` с `<2` вариантами или `correctAnswer` вне диапазона → «всегда неверно»;
- кавычки/переводы строк: внутри `"…"` нельзя экранировать `"` — берите `«ёлочки»` или `'одинарные'`;
- `</script>` внутри текста задания закроет инлайновый скрипт → вся игра исчезнет.
  Так же вредят последовательности `<!--` и `<\/script>` в «неправильных» местах.

## Данные уровней

`LEVELS_CONFIG` (в `levels-textbook.js`) — 50 объектов:

```js
{ id: 24, topics: ["pressure"],    asteroidInterval: 3600, asteroidSpeed: 1.55,
  cityHealth: 110, shieldCapacity: 90, tasksToWin: 10, tasksTotal: 12,
  energySpawnRate: 3000, chapter: "p23", kind: "lesson", description: { key: "level24Desc" } },
```

В файле уровень — одна строка; переносы выше только для читаемости. Поля:

| поле | смысл |
|---|---|
| `topics` | темы, из которых `Teacher` берёт задания для уровня |
| `asteroidInterval` | мс между spawn'ами астероидов (меньше = чаще) |
| `asteroidSpeed` | множитель скорости астероидов |
| `cityHealth` | «здоровье» города: проиграл задание — минус |
| `shieldCapacity` | запас щита, который пополняют решённые задания и `energySpawnRate` |
| `tasksToWin` / `tasksTotal` | сколько решит победой / сколько выдаётся за уровень |
| `energySpawnRate` | мс между «энергетическими» бонусами |
| `chapter` + `kind` | `bonus`+`safety` (уровень 1), `pN`+`lesson` (§-уровни), `lab`+`labN` (лабораторные) |
| `description.key` | ключ подписи уровня в `LOCALES` |



Распределение: `bonus:safety` ×1, `p1…p39:lesson` ×39, `lab:lab1…lab10` ×10 — сверяется
проверкой тем (уровень не должен ссылаться на тему, в которой нет заданий).

Обращайте внимание на смещение: уровень 1 — техника безопасности, поэтому `id: 24` — это §23
(`LEVEL_NAMES_RU[24] === "§23. Давление в жидкостях и газах. Закон Паскаля"`), а `chapter` у него
`"p23"`. Уровни 41–50 — лабораторные, они не привязаны к § напрямую.

Теория перед уровнем собирается функцией `theoryKeyFor(levelId)`:

- `kind === "safety"` или `chapter === "bonus"` → ключ `bonus` (уровень 1);
- `chapter` вида `pN` → конспект `CONSPECT[pN]` (всего 39) + теория `LEVEL_THEORY[pN]`;
- `chapter === "lab"` → ключ `labN` (`LAB_WORKS`, 10 записей);
- иначе — `custom` (урок учителя).

Дополнительно: `CONSPECT_EXPERIMENTS` — 29 экспериментальных заданий по параграфам,
`LEVEL_THEORY` — 51 запись теории, `LEVEL_NAMES_RU/EN/KK` — по 50 названий уровней.

## Переводы интерфейса

`LOCALES = { ru: { … }, en: { … }, kk: { … } }` — по **368** ключей на язык.
Использование: `data-i18n="имяКлюча"` в HTML или `I18n.t("имяКлюча")` в JS.
Добавили кнопку — добавьте ключ в **все три** языка, иначе в интерфейсе покажется `undefined`.

Названия уровней переведены не полностью: для `§`-уровней англ./каз. имена собираются
«упрощённым переводом» (в коде есть пометка `// можно доработать`) — это известный долг,
а не ошибка.

## Встроенные PDF-конспекты

Строки `CONSPECT_PDF_BASE64`, `CONSPECT_PDF_BASE64_EN`, `CONSPECT_PDF_BASE64_KK`
(район строки 7041–7043) — три PDF по **69 страниц**, ≈266 / 227 / 258 КБ. Именно они дают
бóльшую часть веса файла и три гигантские строки. Кнопка «Скачать конспект» в профиле вытаскивает
PDF из нужной строки в `Blob`, поэтому скачивание работает офлайн.

Заменить конспект на новый:

```bash
base64 -w0 Конспект.pdf > /tmp/b64.txt          # одна строка, без переносов
# затем заменить содержимое соответствующей константы в index.html
npm run check                                    # проверит, что это валидный PDF
npm run pdfs                                     # обновит assets/pdf/*.pdf
```

Не пытайтесь «улучшить» файл, перенеся base64 в отдельные `.txt` и подгрузив их через `fetch()`:
после этого игра перестанет работать по `file://` (а это основной способ раздачи ученикам).
